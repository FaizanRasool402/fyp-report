\chaptertitlepage{Methodology}

This chapter presents the research methodology for a multi-architecture chest X-ray disease detection system. The objective is not only to classify respiratory conditions from radiographs, but also to enable a fair and reproducible comparison among three deep learning architectures trained under identical experimental conditions. The pipeline comprises dataset unification, preprocessing and augmentation, model design, training, evaluation with leakage analysis, and Flask deployment with ensemble inference.

\section{From Single-Disease Models to a Unified Benchmark}

An earlier version of this project used three siloed models on incompatible label spaces: binary tuberculosis, COVID-19 multi-class screening (historically including Viral Pneumonia), and binary pneumonia. Those models could not be compared rigorously, because performance differences might reflect dataset differences rather than architectural strength. The revised methodology converts the problem into a unified four-class classification task and trains all three architectures on the same merged dataset, the same patient-grouped splits, the same classification head design (for transfer models), and the same training budget. The locked label order is Normal, Tuberculosis, COVID-19, Pneumonia. Viral Pneumonia from COVID sources is merged into Pneumonia because the Kaggle pneumonia corpus mixes bacterial and viral cases and cannot be separated retrospectively.

\section{Data Collection and Unified Manifest}

No new private clinical datasets were collected. A builder script (\path{training/build_manifest.py}) merges three public sources into \path{training/manifest.csv} with image paths, class labels, patient identifiers, source tags, and train/validation/test assignments.

\subsection{Design Rules for Honest Splits}

\begin{enumerate}
    \item \textbf{Content-hash deduplication.} Byte-identical images are removed so duplicates cannot span train and test.
    \item \textbf{Patient-grouped splitting.} Images from one patient never appear in more than one of train, validation, or test.
    \item \textbf{Fully qualified patient IDs.} Plain stems such as \texttt{0101.jpeg} collide across COVID folders; identifiers are path-qualified and grouped globally.
    \item \textbf{Multi-source Normal and Pneumonia.} Both classes draw from more than one corpus to reduce scanner/dataset shortcutting.
    \item \textbf{Class-size capping with class weights.} COVID-19 remains $130$ after deduplication; other classes were capped at 1{,}200 in the reported run (\texttt{--cap 1200}); residual imbalance uses inverse-frequency weights (COVID weight $\approx$ 2.851).
    \item \textbf{Class$\times$source inspection.} Training proceeds only after confirming Normal and Pneumonia are multi-source.
\end{enumerate}

All images are from public research corpora. The system is a research demonstration and architecture benchmark, not a clinically validated diagnostic device.

\subsection{Augmentation and Class Imbalance}

Geometric augmentation (rotation, translation, zoom, horizontal flip within controlled ranges) is shared across architectures through the common data pipeline. Oversampling of pathological images was avoided; inverse-frequency class weights with categorical cross-entropy emphasise minority-class errors instead.

\section{Model Architectures and Shared Head}

Models are built in \texttt{training/models.py}. Transfer models use an identical head so the benchmark measures the backbone:
\[
\text{GAP} \rightarrow \text{Dropout}(0.5) \rightarrow \text{Dense}(256,\text{ReLU}) \rightarrow \text{Dropout}(0.3) \rightarrow \text{Dense}(4,\text{softmax}).
\]
All models use softmax with categorical cross-entropy, correcting an earlier sigmoid+categorical pairing. There is no warm-start from old single-disease weights.

\textbf{EfficientNetB3.} ImageNet backbone; Phase~2 unfreezes from layer 340 ($\sim$42.7\% of parameters).

\textbf{DenseNet121.} ImageNet backbone; Phase~2 unfreezes from layer 300 ($\sim$42.8\%). BatchNorm remains frozen during fine-tuning.

\textbf{Custom CNN.} Five-block stack (filters $32\rightarrow64\rightarrow64\rightarrow128\rightarrow256$) with BatchNorm, pooling, and dropout; four-class softmax head as a from-scratch baseline.

\section{Evaluation Methodology}

\path{training/evaluate.py} scores every model on the held-out test split: accuracy, balanced accuracy (mean recall), per-class precision/recall/F1, confusion matrices, cross-architecture comparison, and soft-voting ensemble metrics written to \path{training/results/comparison.md}. Soft voting averages probability vectors and takes argmax, preserving confidence that hard majority voting would discard.

\texttt{training/leakage\_probe.py} trains a classifier to predict dataset source versus a majority baseline. Near-baseline performance is desirable; near-perfect source prediction would warn that TB or COVID-19 could be inferred from acquisition cues. COVID-19 recall remains the critical weak point because of small support.

\section{Application Integration Workflow}

Upload (PNG/JPG/JPEG, max 16\,MB) $\rightarrow$ three-stage chest X-ray gate (or Analyse anyway) $\rightarrow$ \texttt{predict\_all()} $\rightarrow$ soft ensemble $\rightarrow$ UI with per-model bars, verdict, and agreement. Weights must be four-wide; legacy \texttt{.h5} files are rejected. Operational sequence: \path{build_manifest.py} $\rightarrow$ \path{train.py --model all} $\rightarrow$ \path{evaluate.py} $\rightarrow$ optional \path{leakage_probe.py} $\rightarrow$ \path{Frontend/app.py}.

\section{Methodological Validity and Limitations}

The design is sound insofar as the task is unambiguous, leakage controls exist, architectures are matched, metrics include per-class recall, and deployment uses training-consistent preprocessing. Known limitations: public datasets are small; COVID recall is statistically unstable; four-class accuracy is expected to be lower than historical binary figures; single-source TB/COVID classes still invite shortcutting (hence the probe); the system is not a clinical device; Grad-CAM and multi-centre validation are future work.

\section{Summary}

The methodology converts three historically separate detectors into a unified, leakage-aware, multi-architecture four-class benchmark with ensemble deployment. Comparative claims are authenticated by shared data and protocol, while evaluation remains transparent about dataset limits and non-diagnostic intent.
