\chaptertitlepage{Literature Review}

This chapter looks at published research on deep learning for chest X-rays, mainly for COVID-19, tuberculosis and pneumonia, which are the three diseases this project covers. It goes through the basic CNN architectures, transfer learning, the datasets used, systems that handle more than one disease, and the gap between good lab results and tools that can actually be used. Each section is linked to a decision we made in our system. The architecture studies explain why we chose DenseNet121 and EfficientNetB3 along with a CNN trained from scratch. The transfer learning work explains our two-phase training. The studies on augmentation and regularization guided our shared training settings, and the papers on deployment explain why we built a Flask app that runs several models together (\textbf{Chapters~3 and~4}).

\section{Deep Learning in Medical Imaging}

Medical image analysis has moved away from hand-made features and classical machine learning towards end-to-end deep learning. In older pipelines, experts had to decide on the features first (texture descriptors, histogram statistics, edge detectors) and then pass them to a classifier such as a support vector machine or a random forest. A CNN does both steps at once. It learns layers of visual patterns straight from the pixels, so no manual feature design is needed, and on clearly defined screening tasks its results are getting close to those of specialists. This matters a lot for chest X-rays, because disease often shows up as small changes in brightness and texture across the lungs. Fixed hand-made features struggle with these patterns, but convolutional layers can learn them well.

\subsection{Foundational CNN Architectures}

Most chest imaging research builds on a small number of well-known CNN designs. Simonyan and Zisserman~\cite{simonyan2014} introduced the VGG networks and showed that a deep network made of small $3\times3$ filters extracts strong features. Stacking several $3\times3$ layers instead of using larger filters adds more non-linearity and a wider view of the image while keeping the number of parameters reasonable. VGG16 and VGG19 are still common baselines for two-class chest X-ray tasks, especially TB screening, where very high accuracy has been reported on public datasets. Their simple structure also makes them easy to fine-tune: you just replace the last fully connected layers with a new classification head.

He et al.~\cite{he2016} proposed ResNet, which uses residual (skip) connections. These solve the degradation problem, where adding more layers to a very deep network actually makes the training error worse. Skip connections let gradients pass straight through identity paths, so networks with hundreds of layers can be trained in a stable way. ResNet versions such as ResNet50 and ResNet50V2 often appear in medical imaging comparisons as reliable general-purpose backbones.

Huang et al.~\cite{huang2017} introduced DenseNet. Inside a dense block, each layer receives the feature maps of all the layers before it, not just the previous one. This helps gradients flow, lets the network reuse features, and needs fewer parameters for the same depth. DenseNet has worked especially well on chest X-rays, where fine texture and opacity details need to survive through the network, and this is why DenseNet121 was adopted for the COVID-19 module in this project.

Tan and Le~\cite{tan2019} proposed EfficientNet, which uses compound scaling to grow the depth, width and input resolution of the network together using one fixed coefficient. Instead of making just one of these bigger, it balances all three, which gives good accuracy for the amount of computation used. This makes EfficientNet a good fit when prediction speed and memory matter. For these reasons EfficientNetB3 was selected for the tuberculosis module in this project after the seven-architecture benchmark study.

\subsection{Large-Scale Chest X-Ray Benchmarks}

Deep learning for chest X-rays got a lot of attention after CheXNet by Rajpurkar et al.~\cite{rajpurkar2017}. They trained DenseNet121 on ChestX-ray14~\cite{wang2017} and showed that it could detect pneumonia about as well as radiologists on a held-out test set. CheXNet gave a sigmoid probability for pneumonia and was trained on more than 100,000 frontal chest X-rays labelled with fourteen chest diseases. After this work, DenseNet became a standard baseline for chest X-ray tasks, and many follow-up studies were done on other lung diseases. The study also showed that, on large medical datasets, deep learning can match specialists when the task is clear and the evaluation is careful.

Irvin et al.~\cite{irvin2019} released CheXpert, a set of 224,316 chest X-rays labelled for 14 conditions. The labels came from a rule-based labeller, and radiologists reviewed the uncertain cases. Their DenseNet121 baseline reached radiologist-level results on five main conditions, including pneumonia and pleural effusion. It used a loss that handles uncertain labels directly instead of forcing them to be positive or negative. CheXpert and similar large datasets showed that deep learning is more than a research idea and can be clinically useful for chest X-rays, as long as label noise, class imbalance and differences between hospitals are handled with careful preprocessing and validation. The size of CheXpert also showed that training on many diseases at once needs far more data than a student project has, which supported the modular single-task model approach adopted in this report.

Taken together, these benchmark studies point to three ideas that come up again and again. (1) Starting from ImageNet weights is almost always done for chest X-ray tasks, because medical datasets rarely have enough images to train a very deep network from scratch without overfitting. (2) The choice of architecture affects both the best accuracy and the cost of running the model, as the VGG versus EfficientNet trade-off in this project's TB benchmark showed. (3) The size of the dataset and the quality of its labels decide how well a model works on new data, so high accuracy on a public Kaggle dataset does not mean the model will work on images from another hospital or scanner without more testing. All three ideas shaped our method: transfer learning with phased fine-tuning for COVID-19 and TB, a systematic comparison of architectures to choose the TB model, and testing all three models on fixed held-out splits.

\section{COVID-19 Detection from Chest X-Rays}

The COVID-19 pandemic sped up research on automatic screening from portable chest X-rays. Emergency departments and low-resource hospitals needed fast triage, and RT-PCR testing was often limited or slow. Portable X-ray machines could be used at the bedside in intensive care units and field hospitals and could produce images within minutes. Automatic reading of these images offered a second route alongside lab testing when test kits or lab capacity ran out.

Wang et al.~\cite{wang2020} introduced COVID-Net, a custom CNN built for three classes: COVID-19, non-COVID pneumonia and normal. They reported sensitivity above 90\%. The study focused on designing the network for the task, for example using depthwise separable convolutions and tailored filter banks, instead of only using ready-made ImageNet classifiers. Their results showed that COVID-19 opacities look a lot like other kinds of pneumonia. This is still a problem for multi-class systems, and it is one reason we use a single shared set of four classes.

Chowdhury et al.~\cite{chowdhury2020} published the COVID-19 Radiography Database, one of the public sources merged into our manifest. They showed strong results for COVID-19 versus normal on this data. In our system, these images supply the COVID-19 class (and Normal or Pneumonia labels where they exist). ``Viral Pneumonia'' images from the COVID sources are put into the shared Pneumonia class, because the Kaggle pneumonia dataset mixes bacterial and viral cases and they cannot be separated again. The images are stored in folders named by class, so they can be loaded by folder when the manifest is built.

Rahman et al.~\cite{rahman2021} studied how image enhancement and preprocessing affect COVID-19 detection. They found that the right contrast normalisation and enhancement can improve accuracy by several percentage points. This supports using standard preprocessing that matches each model. We follow this in all three models: each uses its own normalisation (\texttt{preprocess\_input} for DenseNet and EfficientNet, division by 255 for the custom CNN) and is resized to its own expected input size.

Zhang et al.~\cite{zhang2020} introduced confidence-aware loss functions for COVID-19 detection, which make predictions more reliable when labels are uncertain. Their model reached 96\% sensitivity while keeping false positives under control. This matters clinically, because a screening tool should miss as few cases as possible without sending too many people for isolation or referral. During an outbreak, a false negative can let the disease keep spreading, while too many false positives can fill up isolation capacity.

Overall, the COVID-19 literature shows that DenseNet-type networks, fine-tuning in more than one phase, and careful handling of COVID-19 versus other opacities are key to a useful multi-class screening tool. In this project DenseNet121 is one of the three architectures trained on the shared 4-class task, from the same family as CheXNet~\cite{rajpurkar2017}. Our two-phase training (first a frozen backbone, then partial unfreezing) follows the step-by-step fine-tuning recommended by Raghu et al.~\cite{raghu2019}. Making COVID-19 one of four shared output classes, instead of a separate single-disease app, solves the comparison problem described in Section~\ref{sec:lit-gaps}. These choices appear in the shared training code described in \textbf{Chapter~3} and are evaluated in \textbf{Chapter~5}.

\section{Tuberculosis Detection}

Tuberculosis is still one of the leading infectious causes of death in the world. The World Health Organization~\cite{who2022} reports more than 1.5 million TB deaths every year, and late diagnosis keeps the disease spreading, especially in high-burden areas with few radiologists. Chest X-rays play a central part in TB screening. Signs such as upper-lobe infiltrates, cavities and pleural effusion can point to active disease even before lab confirmation is available. Automatic TB detection from frontal chest X-rays is therefore a clear screening task with real public health value.

Jaeger et al.~\cite{jaeger2014} set up the first standard TB detection benchmarks using the public Montgomery County and Shenzhen Hospital datasets. These came with standard evaluation splits, so different algorithms could be compared fairly. Before these datasets were released, TB studies used their own private data, which made it hard to compare results. The Montgomery and Shenzhen datasets are still reference points for both classical and deep learning TB research, and they influenced the later Kaggle TB datasets used in this project~\cite{tbkaggle}.

Lakhani and Sundaram~\cite{lakhani2017} used an ensemble of GoogLeNet and AlexNet~\cite{krizhevsky2012} on chest X-ray datasets and reached AUC values of 0.99 and 0.97 respectively. This was among the first studies to show that deep learning could match or beat radiologists at classifying TB from frontal chest X-rays. Their ensemble combined two architectures that look at the image in different ways, which is similar in spirit to the multi-architecture comparison done for the TB module in this project.

Hwang et al.~\cite{hwang2016} showed that a CNN trained on more than 40,000 chest X-rays reached an AUC of 0.96 for TB screening. This showed the value of large-scale training even before ImageNet transfer learning became common in medical imaging. Their work suggests that, with enough labelled examples, a large dataset can make up for a simpler architecture.

More recent studies have compared modern architectures on Kaggle TB datasets. They usually find that fine-tuned VGG models reach very high accuracy on the two-class Normal versus Tuberculosis task, while EfficientNet models give similar accuracy at a lower computing cost. Tan and Le~\cite{tan2019} showed that compound scaling lets EfficientNetB3 come close to the accuracy of heavier networks while costing less to run. This trade-off is why we included EfficientNetB3 in our 4-class comparison, together with DenseNet121 and a custom CNN.

From the TB literature we take two points. First, architectures need to be compared properly, because the best accuracy on a single two-class task does not carry over automatically to a harder shared multi-class problem. Second, two-class TB screening on cleaned public datasets can reach near-perfect accuracy when transfer learning and regularization are used correctly, but those numbers cannot be compared with 4-class, patient-grouped results. Real-world performance still needs solid preprocessing, testing on held-out data and clinical validation.

\section{Pneumonia Detection}

CNN-based pneumonia detection has been tested many times on the Kaggle Chest X-Ray dataset shared by Mooney~\cite{mooney2018}. It contains chest X-rays of children labelled NORMAL or PNEUMONIA, about 5,863 images split into training, validation and test folders. With a dataset of this size, overfitting is a known risk, so regularization is needed. Because the train, validation and test folders are fixed in advance, researchers can report results on the same test set and compare architectures under the same conditions.

Studies on this dataset regularly report accuracy above 90\%, using everything from simple sequential CNNs to complex transfer learning models. Rajpurkar et al.~\cite{rajpurkar2017} and later CheXpert-related work~\cite{irvin2019} treat pneumonia as one of the most studied chest X-ray findings, with CNNs learning the opacity, consolidation and interstitial changes caused by bacterial and viral infection. On frontal X-rays of children, pneumonia usually appears as increased opacity in one or both lungs, often with air bronchograms visible inside the consolidated areas. Convolutional filters can learn these patterns when there are enough labelled examples.

Batch normalization, dropout and learning rate scheduling are repeatedly shown to help models generalise on a dataset of this size. Batch normalization keeps the activations stable across mini-batches. Dropout switches off random neurons during training so they do not depend too much on each other. Reducing the learning rate when progress stalls allows smaller, finer weight updates once the validation loss stops improving. Shallow to medium-depth custom CNNs are still competitive when training time, model size and an easy-to-understand architecture matter more than a small accuracy gain from a very deep transfer learning backbone. This is why we designed the five-block custom CNN used as Model~3.

Rahman et al.~\cite{rahman2021} also looked at preprocessing for pneumonia and COVID-19 classification. They noted that pixel normalisation, the resize method and the colour channel order all affect predictions, especially when images are loaded with OpenCV and converted between BGR and RGB. Our shared preprocessing handles this the same way for all models. If preprocessing during training and during prediction does not match, performance can drop without any obvious error, which is a common problem in deployed medical AI systems.

The Kaggle pneumonia dataset only labels images as NORMAL or PNEUMONIA and does not give the type or cause of pneumonia. We map these folders to the shared Normal and Pneumonia classes of our 4-class label set, together with the TB and COVID sources, so that all models are compared using the same output classes.

\section{Transfer Learning}

Transfer learning from models pre-trained on ImageNet~\cite{deng2009}, including VGG16~\cite{simonyan2014}, InceptionV3, ResNet50~\cite{he2016}, DenseNet121~\cite{huang2017} and EfficientNet~\cite{tan2019}, has become the standard approach in medical imaging AI when labelled medical data is limited. ImageNet has over a million natural images in a thousand categories. Training on it teaches a model general low-level features such as edges, textures and shapes, and these still work on X-rays even though X-rays look very different from normal photos. Medical datasets rarely have enough images to train a very deep network from random weights without heavy overfitting.

Raghu et al.~\cite{raghu2019} studied how well transfer learning works for medical imaging in their Transfusion study. They found that low-level features transfer well, but higher-level features need fine-tuning for the new task. They also saw that freezing the early layers and then gradually unfreezing deeper blocks (or first training a new head before full fine-tuning) often works better than training from random weights on small medical datasets. Keeping the backbone frozen at the start stops large gradient updates from damaging the pre-trained features before the new head has learned anything useful.

This finding directly shaped the two-phase training of the DenseNet121 COVID-19 model. In Phase~1 the backbone is frozen and only the new head is trained, with a learning rate of $10^{-4}$. In Phase~2 the upper backbone layers from index 300 onwards are unfrozen and trained with a lower learning rate of $10^{-5}$ to adapt them to X-rays. The EfficientNetB3 TB model follows the same idea: the ImageNet backbone starts frozen, and the head is trained with in-graph augmentation before the weights are saved for deployment.

The literature also warns that transfer learning does not guarantee good results on new data. On small public datasets, performance can look better than it really is because of train-test leakage, repeated tuning on the validation set, or dataset-specific artifacts such as hospital borders or text on the image that the model learns to use as a shortcut. Fixed random seeds, a held-out test set, and comparing architectures on the same splits (as in the TB benchmark with seed 1337) are the recommended practices from this work.

\section{Data Augmentation and Regularization}

Medical imaging datasets are usually small compared with natural image datasets, so augmentation and regularization are very important for avoiding overfitting. Augmentation makes the training set effectively bigger by applying changes that do not change the label, which pushes the model to learn general features instead of memorising exact pixels. The literature points to a few augmentations that work well for chest X-rays: random rotation and horizontal flips (since frontal X-rays are roughly symmetric left to right), width and height shifts to imitate small changes in patient position, zoom changes to imitate different image scales, and other geometric changes that keep the intensity the same. These are applied during training only.

Dropout, batch normalization, early stopping, reducing the learning rate on a plateau, and model checkpointing show up again and again in the best lung classification studies. Early stopping watches the validation loss and stops training if it does not improve for a set number of epochs, so the model does not keep fitting noise. Checkpointing saves the best weights seen during training instead of the weights from the last epoch, which may already be overfitted. Irvin et al.~\cite{irvin2019} and Chowdhury et al.~\cite{chowdhury2020} both use augmentation together with regularization when fine-tuning deep networks on unbalanced disease labels.

For both two-class and multi-class models (sigmoid or softmax outputs), class imbalance is common in pneumonia datasets, where positive cases can make up most of some splits. It is often handled by augmenting the smaller class, splitting the data carefully by class, and using early stopping, rather than simply chasing accuracy. Accuracy can be misleading when classes are unbalanced: a model that always predicts the largest class can show high accuracy while getting every minority case wrong. We use these techniques in the same way for all three models, with augmentation settings adjusted to each model's input size and design. For example, DenseNet121 uses \texttt{ImageDataGenerator} with rotation and shift settings, while EfficientNetB3 puts \texttt{RandomZoom} and \texttt{RandomRotation} directly inside the Keras model.

\section{Multi-Disease Detection Frameworks}

Systems that detect several diseases have received much less attention than single-disease work. There are many studies on individual diseases (COVID-19 detection, TB screening, pneumonia classification), and each reports good accuracy on its own. But most of these tools cover only one disease and report offline numbers without being part of a single clinical workflow. In practice, a doctor who suspects more than one possible cause would need to run several separate apps, each with its own interface, preprocessing and output format. This is not practical in emergency triage, where speed and simplicity matter most.

CheXpert~\cite{irvin2019} and CheXNet~\cite{rajpurkar2017} show multi-label prediction from one model trained on many diseases at once. However, this needs very large labelled datasets, and it gives all predictions together instead of letting the user screen for a specific suspected condition. In real triage, doctors often work through a list of possible diagnoses: they might suspect TB where it is common, COVID-19 during an outbreak, or community-acquired pneumonia in a child.

Our framework fills this gap by training three architectures (EfficientNetB3, DenseNet121 and a custom CNN) on one shared four-class dataset (Normal, Tuberculosis, COVID-19, Pneumonia). This makes the comparison fair, and every model can name the same diseases. Each backbone keeps its own input size and preprocessing (DenseNet $224\times224$, EfficientNet $256\times256$, custom CNN $150\times150$), but they all use the same splits, seed, augmentation budget, the same head design for the transfer models, and a softmax output over four classes. The Flask app runs every available model on each upload and combines their probabilities with soft voting. It shows where the models agree and disagree, instead of making the user pick one disease model first. This kind of modular, multi-architecture design with one shared label set is not common in published medical AI work, which usually reports single-disease notebooks or trains one large multi-label network on datasets like CheXpert without a controlled comparison of backbones.

\section{Deployment and Clinical Translation}

A common criticism of medical AI research is the ``deployment gap''. Many studies report accuracy, sensitivity and AUC on past datasets but never deliver software that doctors can use. Abadi et al.~\cite{abadi2015} and the TensorFlow tools that followed made it practical to save models and run them at scale, which made deployment easier. Even so, published chest X-ray studies often stop at a notebook. They report test-set numbers but do not show that a non-expert can reliably use the model through a stable interface. This matters, because a model with 95\% accuracy in a controlled experiment is of no practical use if it cannot be loaded, fed the right input and run reliably in a hospital or community setting.

A usable system needs more work than just training the model. It needs input checks in several stages to reject uploads that are not X-rays. It needs preprocessing at prediction time that exactly matches training (including bilinear resizing instead of the default nearest-neighbour). It needs lazy loading of models so the app starts quickly even with several large weight files, and safe handling of requests that arrive at the same time. Bradski~\cite{bradski2000} established OpenCV as a standard library for reading and checking images. We use it in the three-stage chest X-ray check (monochrome check, radiograph envelope features and anatomy check) that runs before prediction.

Lightweight Flask-based~\cite{flask} web apps have become a common, easy way to deploy medical AI in student and research prototypes. In this project, the Flask app has an upload page that takes an image file, checks it, runs \texttt{predict\_all()} on every trained 4-class model, and shows probability bars for each model together with a soft-voting ensemble, without asking the user to choose a disease model. Because prediction runs on the server, the model weights and TensorFlow stay on the server. Clinical deployment at a regulatory level is a separate matter from research prototypes, but a working interface is still needed for a project to be credible, even for an academic final year project.

This project tackles the deployment gap directly with a single Flask web app that runs all three 4-class models and presents their combined result, which answers the gap described in Section~\ref{sec:lit-gaps}.

\section{Explainability and Trust}

Doctors will only use AI screening tools if they can understand and trust them, not just if the tools are accurate. A doctor who gets a prediction without knowing what it is based on is unlikely to rely on it for triage, especially when it does not match their own judgement. Selvaraju et al.~\cite{selvaraju2017} introduced Grad-CAM (Gradient-weighted Class Activation Mapping), which creates heatmaps showing the parts of an image that most affected a CNN's prediction. Grad-CAM takes the gradient of the target class score with respect to the feature maps of a chosen convolutional layer and produces a rough map that can be laid over the X-ray.

Grad-CAM and similar methods have been used on chest X-ray models to check that they look at sensible areas, such as the lungs, rather than borders, text or other dataset artifacts. If a model highlights a hospital name printed on the edge of the image instead of the lung opacities, the heatmap exposes a false shortcut that accuracy numbers alone would hide. Even with all this interest, explainability is rarely built into multi-model screening systems with one interface. Most explainability studies look at a single model and a single disease. Adding Grad-CAM or a similar visual explanation to a multi-disease system is still open future work, as noted in the research gaps below and in \textbf{Chapter~6}.

\section{Gaps in Existing Research}
\label{sec:lit-gaps}

Deep learning for chest X-rays has made a lot of progress, but turning research results into multi-disease screening tools that doctors can use is still unfinished. Many studies report strong accuracy on cleaned public datasets, but few deliver complete software that a doctor could actually use during triage. The gaps below are not just theory. They directly shaped the design decisions, architecture choices and deployment work described in \textbf{Chapters~3 to~5}. Closing them needs better models, but also attention to software integration, careful validation and user-facing deployment, which get much less attention in published work than new architectures do.

\begin{enumerate}
    \item \textbf{Single-disease models that cannot be compared:} Separate student or demo classifiers with different label sets make fair comparison impossible and split the user's work across several tools.
    \item \textbf{Splits that ignore leakage:} The same patient or the same file in both training and test data makes the reported accuracy look better than it is.
    \item \textbf{Reporting only accuracy:} A single accuracy number hides poor recall on small classes (especially COVID-19, which has few images).
    \item \textbf{Training and app mismatch:} Resizing or normalising images differently in the app than in training quietly lowers the quality of live predictions.
    \item \textbf{Weak input checks:} Checking only whether an image is monochrome still lets many non-X-ray images through.
    \item \textbf{No visible model disagreement:} Few demos show where models disagree alongside the combined result.
\end{enumerate}

\section{Summary}

Past research supports using CNNs and ImageNet transfer learning for chest X-rays, but it also warns that small COVID datasets, dataset shortcuts and reporting only accuracy make results hard to trust. Careful data handling (patient-grouped splits, removing duplicate images), the same training setup for a fair comparison of backbones, and usable interfaces that clearly state they are not for diagnosis are all essential. This project responds with a shared four-class comparison of several architectures, evaluation that checks for leakage (including a source probe), and a Flask ensemble app with a tested X-ray check. Grad-CAM-style explanations are left for future work.
